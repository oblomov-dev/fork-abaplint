Closes #2384

### Problem
`unsecure_fae` reports every FOR ALL ENTRIES, the check for an initial driver table was a todo:
```abap
IF it IS NOT INITIAL.
  SELECT * FROM t000 FOR ALL ENTRIES IN @it WHERE mandt = @it-table_line INTO TABLE @lt_t000.
ENDIF.
```

### Change
The driver table counts as checked, and no issue is reported, if
- the SELECT is in the IF or ELSEIF branch of `itab IS NOT INITIAL`, `NOT itab IS INITIAL` or `lines( itab ) > 0` (also `GT 0`, `<> 0`, `>= 1`), alone or AND-combined, also in a parenthesized AND sub-condition;
- or `IF itab IS INITIAL. RETURN. ENDIF.` (condition alone or OR-combined, body only RETURN, no ELSE) or `CHECK itab IS NOT INITIAL.` (the variant from #2384) precedes the SELECT in the same method, form or function module, at the same or an outer block level, not inside a loop;

and the table is not written (Target / FSTarget) between the check and the SELECT, or in a loop around the SELECT within the checked region. For tables that are not local variables or parameters (attributes, `me->x`, field symbols), a method/function/form call in between also invalidates the check. Kept conservative on purpose: OR in the guard, ELSE branch, NOT ( ... ), dynamic driver names are still reported. The rule documentation describes the scope and now has a bad/good example.
