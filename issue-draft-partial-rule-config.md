# Rule configured as an object: omitted options are not defaulted, the rule silently checks nothing

**Title:** Rule config object without all options: omitted options are falsy instead of default

## Problem

When a rule is configured as an object, `Config.getEnabledRules()` passes that object to
`rule.setConfig(ruleConfig)` as it is. Options that the object leaves out are `undefined`,
not the default of the rule's `...Conf` class. Many rules test options with `=== true`,
so a partial object switches those checks off without any message.

Example, `check_subrc`. The intent is "default behaviour, but exclude some files":

```json
"check_subrc": {
  "exclude": ["/src/legacy/"]
}
```

Result: `openDataset`, `readTable`, `selectSingle`, ... are all `undefined`, `check_subrc.ts`
tests `config.readTable === true`, so the rule reports nothing anywhere.

Reproduction against 2.120.117:

```abap
DATA lt_tab TYPE STANDARD TABLE OF i WITH DEFAULT KEY.
DATA lv_i TYPE i.
READ TABLE lt_tab INDEX 1 INTO lv_i.
WRITE lv_i.
```

| rule config | issues |
|---|---|
| `"check_subrc": true` | `check_subrc` |
| `"check_subrc": {"exclude": []}` | none |
| `"check_subrc": {"exclude": [], "readTable": true}` | `check_subrc` |

We ran into this in four repositories. The configs had been reduced by hand to the
options that differ from the defaults. Rules that test options with `=== false`
(for example `suspicious_loop.unchangedCondition`) keep working with a partial object,
so the behaviour also differs from rule to rule.

## Proposal

Merge the rule's default options under the configured object in `Config.getEnabledRules()`,
for example:

```ts
} else if (typeof ruleConfig === "object") {
  rule.setConfig({...rule.getConfig(), ...ruleConfig});
```

(`rule.getConfig()` before `setConfig` holds a new `...Conf` instance with the defaults, as
`object_naming` already falls back per option, see #2153.)

This changes behaviour for configs that rely on omitted options being off. If that is too
much for a minor release, alternatives are a warning for each option missing from an object
config, or adding the change to the 3.0.0 collection (#543). Related: #3923 (config in YAML and rulesets), #398 ("Extend default" ruleset).

Happy to open a PR for whichever variant you prefer.
